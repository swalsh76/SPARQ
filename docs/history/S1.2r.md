3. A settings file named in `SPARQ_ANALYTICS_CONFIG` but missing, or unreadable, was silently ignored. **Fixed:** refused; only the default path may be absent; tests.
4. A settings error other than bad TOML (a file that cannot be read or decoded) gave a traceback in the history and study command lines. **Fixed:** every read error is a settings error, and every command line reports it the same way; tests.
5. A relative scratch path or one with `~` was taken as given. **Fixed:** `~` expanded, an absolute path required, the folder resolved; tests.
6. CLAUDE.md and the PLAN's S1.2r row still said S1.2r was parked and the variables set by hand. **Fixed.**
7. The node's new settings file was in no deploy guide. **Fixed:** `docs/deploy/ANALYTICS.md`, with the file, its check and its refusals.
8. The same call and error handling was pasted into seven command lines with special cases in two. **Fixed:** one `scratch.ready()`, called first by each.
9. Only three command lines were tested for the refusal. **Fixed:** all seven.
10. The scratch folder was not checked for being writable, and the unknown-setting check ran after the others. **Fixed:** a folder the account cannot write is refused; unknown settings are reported first; test.
